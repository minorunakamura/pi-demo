# ブラウザ版リバーシ 基本設計

## 目的

PCのChromeで、コンピューター相手に気軽に1局遊べるリバーシを作る。
起動後すぐに対局でき、CPUの打ち方に意図を感じながら、終局と再戦まで迷わず操作できることを目指す。

本書は会話で確認した要件と、それに対する設計方針を整理したもの。実装計画や、実装開始の承認を表すものではない。

## 確認済みの要件と範囲

- 対象はPCのChrome。スマートフォンや他のブラウザへの対応は含めない。
- TypeScriptで作り、ローカルサーバーを起動してブラウザから開く。HTMLファイルの直接起動は対象外。
- 標準の8×8盤面で、人間とCPUが対戦する。
- CPUは気軽に楽しめる強さとし、ランダムや目先の石数だけでなく、少し先を考える。
- CPUの思考時間は1秒以内とする。
- 対局の保存・復元、戦績の記録は行わない。再読み込みやタブを閉じた場合、対局状態は保持しない。
- 対人戦、オンライン対戦、難易度選択は今回の範囲に含めない。

## 構成と責務

Vite + 素のTypeScript + HTML/CSSを設計案とする。
画面規模が小さいためUI frameworkは導入せず、ゲーム処理はすべてブラウザ内で完結させる。
Viteは開発時のTypeScriptの変換と配信に使い、ゲーム処理用のバックエンド、データベース、外部AIサービスは設けない。

主要な責務は次のように分ける。ファイル構成や具体的なAPIは後続のPlanningで定める。

| 役割 | 責務 |
| --- | --- |
| ルール | 合法手、石の反転、手番、パス、終局、石数と勝敗を判定する |
| CPU | 現在の局面から、時間制限内で合法手を選ぶ。ルール判定は人間の操作と共通にする |
| 対局の進行と画面 | 入力を受け付け、ルールに従って状態を更新し、CPUの思考と表示をつなぐ |

盤面、手番、対局の進行状態をブラウザのメモリ上で管理する。
CPUの探索は仮の局面で行い、実際の盤面は着手が確定したときだけ更新する。

## 対局の流れ

プレイヤーを黒・先手、CPUを白・後手とする案で整理する。

1. 起動時に初期盤面を表示し、プレイヤーの入力を受け付ける。
2. プレイヤーが合法手を選ぶと、石を置いて反転させる。不正なマスへの入力では局面を変更しない。
3. CPUの手番に切り替え、思考中であることを表示する。この間、プレイヤーは着手できない。
4. CPUが選んだ手を反映し、次の手番に進む。
5. 手番側に合法手がなければ、理由を表示して自動パスする。双方に合法手がなければ終局する。
6. 終局時は石数と勝敗を表示する。同数なら引き分け。最終盤面は残す。
7. 終局後は「もう一度遊ぶ」で新しい対局を開始できる。途中でも「最初から」でやり直せる。

やり直した場合は以前の対局を終了し、以前のCPUの思考結果が新しい対局に反映されないようにする。

## CPUの判断

### 読みと評価

基本は、CPUの候補手と、それに対するプレイヤーの応手まで読む。
プレイヤーがCPUにとって最も不利な応手を選ぶと仮定し、それでも評価がよい候補を選ぶ。
探索中も実際の対局と同じパス・終局のルールを適用する。

盤面の評価には次を使う。

- **角**：取った石を返されないため、高く評価する。
- **合法手の数**：自分の選択肢が多く、相手の選択肢が少ない局面を好む。
- **石数**：序盤は重視しすぎず、終盤ほど重視する。終局した局面は最終的な勝敗を優先する。

評価の配分と終盤への切り替え方は未調整。
最初から深い探索や、意図的な悪手による手加減は導入しない。
速いPCでも、時間が余ったことだけを理由に読みを際限なく深くしない。

### 思考時間の制限

CPUの思考時間は1秒以内とし、着手・表示にも余裕を残すため、探索の計算予算は暫定で最大800ms程度とする。
時間を使い切ることを目標にはせず、早く決まればそのまま着手する。

- 探索前に、時間切れでも選べる合法手を確保する。
- まず浅い読みを完了させ、次にプレイヤーの応手まで読む。
- 探索中に経過時間を確認し、予算に達する前に打ち切る。
- 深い読みが完了しなかった場合は、全候補の評価を完了した浅い読みの結果を使う。それもなければ、確保した合法手を使う。

通常の前面タブでCPUの手番開始から着手まで1秒以内に収まることを、実装後に確認する。
ただし、OSの一時停止やChromeのバックグラウンド制限まで含めた厳密な実時間保証はできない。
この実行環境上の制約と、計算予算の妥当性は未検証事項として扱う。

## 画面の方針

PC向けのシンプルな1画面構成とする。

- 中央に8×8の盤面を大きく表示する。
- 手番、黒白の石数、CPU思考中・パス・終局などの状況を表示する。
- 合法手と直前の着手を見分けられるようにする。
- 対局中は「最初から」、終局後は「もう一度遊ぶ」を用意する。
- 手番や状態は色だけに頼らず、文字でも伝える。盤面の操作はキーボードからも行えるようにする。

具体的な色、余白、装飾は未指定。盤面の見やすさと操作の分かりやすさを優先し、詳細は実装時に調整する。

## 残る不確実性と確認する観点

基本構成や主要な流れを止める未決事項はないが、以下は実装・対局で確かめる必要がある。

| 項目 | 設計への影響と確認の観点 |
| --- | --- |
| CPUの楽しさ | 読みの深さだけで適度な強さは保証できない。実際の対局で、目先だけの不自然な手が少なく、気軽に勝負できるかを確認し、評価の配分や読みの深さを調整する |
| CPUの応答時間 | 800msの計算予算で着手まで1秒以内に収まるかは未計測。対象環境で、遅い局面でも時間内に有効な手を返し、操作や表示を不必要に妨げないかを確認する |
| 対局の成立性 | 通常の着手だけでなく、片側のパス、双方が打てない終局、引き分け、CPU思考中のやり直しでも状態が矛盾しないことを確認する |

確認のために必要な具体的なテストや実装手順は、後続のPlanningで定める。

## 根拠

- このセッションでのユーザーとの設計議論。対象環境、TypeScriptとローカルサーバーの利用、CPUの方向性、1秒以内の思考時間、保存不要を確認した。
- 作業ディレクトリの初期確認では既存のソースやプロジェクト規約が見つからず、新規設計として整理した。
- Viteによる構成、画面と対局の詳細、CPUの探索・評価方式は、上記要件に対する設計案。実装済み・性能検証済みを意味しない。
